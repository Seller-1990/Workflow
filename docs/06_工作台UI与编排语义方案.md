# 工作台 UI 与编排语义方案（V1）

> 目标：把当前工作流管理应用从“表单 + 表格拼接”整理为“工作台式编排界面”，同时收敛配置项，统一执行语义。

## 1. 已确认的核心语义

### 1.1 阶段
- 阶段是**固定的大顺序屏障**。
- 后一阶段必须等待前一阶段全部完成后才能开始。
- 阶段的作用不是单纯分组，而是执行边界。

### 1.2 上游依赖
- 上游依赖只描述**某个步骤依赖哪些具体步骤**。
- 它是步骤级的精确等待关系。
- 默认提供三种入口：
  - 无显式依赖
  - 依赖上一步
  - 自定义依赖

### 1.3 检查点
- “前置”统一改名为**检查点**。
- 检查点表示：**该步骤是本阶段内的闸门步骤**，其他同阶段步骤必须等它完成。
- 检查点不是普通依赖，不应和上游依赖混成一个概念。

### 1.4 并行
- 只保留**工作流级自动并行**。
- 不再提供步骤级并行开关。
- 步骤是否并行由依赖关系 + 阶段屏障 + 检查点自动决定。

## 2. 视觉与结构

### 2.1 页面结构
- 左侧：工作流列表、搜索、资产入口
- 中间：主工作区
  - 编排
  - 运行
  - 配置
- 右侧：Inspector（上下文详情）

### 2.2 编排页
- 默认展示阶段泳道。
- 每个阶段内显示步骤卡片。
- 卡片只展示必要信息：
  - 步骤名
  - 类型
  - 文件名
  - 状态 / 耗时
  - 上游依赖摘要
  - 检查点 badge

### 2.3 运行页
- 只保留运行时间线、执行批次、实时日志、失败摘要。
- 不再把编排设置混进运行区域。

### 2.4 配置页
- 只放低频全局设置：
  - 自动并行
  - 最大并行数
  - 监听
  - 通知
- 不再放步骤级并行、前置等概念。

### 2.5 按钮与空白区
- 所有按钮都必须有明确用途，不能只靠颜色或图标猜。
- 仅图标按钮必须同时具备：
  - 可读名称
  - hover tooltip
  - 无障碍名称
- 主操作使用蓝色。
- 次级操作使用白底/浅底。
- 危险操作只使用红色，不再用粉色混淆语义。
- 右侧 Inspector 的空白区不是留白装饰，而是上下文区域：
  - 未选中步骤时展示工作流摘要、快捷说明、常用操作
  - 选中步骤时展示编辑项、删除入口、依赖摘要

## 3. 交互规则

### 3.1 阶段选择
- 点击某个阶段后，该阶段成为当前上下文。
- 点击“添加步骤”时，新步骤默认加入当前阶段。
- 如果当前有步骤被选中，则仍以其所属阶段作为默认阶段上下文。

### 3.2 步骤拖拽
- 拖拽步骤到其他阶段：只改变阶段归属。
- 在同一阶段内拖拽：只改变顺序。
- 拖拽后，阶段计数、Inspector、摘要标签同步更新。

### 3.3 Inspector
- 选中步骤时，Inspector 显示步骤编辑。
- 选中阶段时，Inspector 显示阶段信息，并允许新增步骤。
- 关键字段直接编辑，低频字段折叠到高级区。
- 删除步骤的稳定入口放在 Inspector 的操作区，按钮文案明确为“删除步骤”，并配红色危险样式与二次确认。
- 阶段删除不放在步骤区，放在阶段标题菜单或阶段操作区。

### 3.4 检查点
- 检查点只作为少数关键步骤使用。
- 勾选后，卡片显示检查点标识。
- 同阶段其他步骤在执行计划中必须等待该检查点完成。

### 3.5 快捷操作
- 步骤卡片右键或悬停动作区提供快捷删除、复制、移动阶段。
- 阶段标题区提供新增步骤、上移/下移、删除阶段。
- 任何危险操作都必须先确认。

## 4. 字段与数据映射

### 4.1 保留并前台暴露
- `stage_uid`：执行阶段
- `depends_on`：上游依赖
- `is_gate`：检查点
- `workflow.parallel_enabled`：自动并行开关
- `workflow.max_workers`：并行上限

### 4.2 保留但不再前台暴露
- `step.is_parallel`

### 4.3 前台文案
- `前置` -> `检查点`
- `依赖` -> `上游依赖`
- `并行` -> 仅作为工作流级配置

## 5. 编辑器最小化字段

### 5.1 基础区
- 步骤名称
- 类型
- 脚本 / 文件
- 执行阶段

### 5.2 顺序区
- 上游依赖：无 / 依赖上一步 / 自定义
- 检查点：本阶段先单独执行

### 5.3 高级区
- 参数
- 工作目录
- 超时
- 重试次数
- 上次成功则跳过
- 图表主题覆盖

## 6. 执行规则

1. 阶段顺序固定。
2. 阶段内按依赖与检查点计算执行批次。
3. 同一依赖层在启用自动并行时可并行执行。
4. 检查点步骤始终独立执行，不与同层步骤并行。
5. 上游依赖优先于纯阶段顺序判断。

## 7. 交付顺序

### 第 1 步
- 统一语义与文案
- 调整 Inspector 字段分组
- 隐藏步骤级并行

### 第 2 步
- 落地阶段选择 + 新增步骤只进当前阶段
- 落地拖拽跨阶段 / 同阶段排序

### 第 3 步
- 落地检查点视觉与执行计划
- 收敛步骤表、DAG、运行页的状态展示

### 第 4 步
- 清理遗留字段的前台暴露
- 补充验证与回归测试

## 8. 验证标准

- 选中阶段后，新建步骤默认进入该阶段
- 拖拽步骤后，阶段归属和顺序正确变化
- 检查点只影响同阶段内的执行门槛
- 工作流级自动并行行为与当前执行引擎一致
- 界面上不再出现步骤级并行开关
- 所有按钮 hover 时都能看到名称和作用
- 删除步骤有稳定可见入口，不需要猜测
- 右侧空白区在无选中状态下也能提供有用信息
