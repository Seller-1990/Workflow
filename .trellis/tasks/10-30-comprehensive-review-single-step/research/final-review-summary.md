## Implementation consequences

- UI entry points share `StepEditorPanel.should_modify_run_args()` and retain the existing run-request signal shape and RunWorker argument contract.
- Legacy `confirm_risky_paths(workflow_id, step_uids=None)` and digest helpers remain compatible but have no runtime gate caller. Do not turn their historical metadata into a new authorization requirement.
- `RunPlan.with_selected_steps()` retains complete snapshots. Its now-optional derivation was left intact in this bounded change; `evaluate_run_plan()` is a compatibility no-op.
- CLI cancellation uses this run's finished status, metadata is not borrowed from unrelated history, auxiliary pools are shut down, and mutually exclusive run modes reject ambiguous input.
- Initialization errors retain the created run context for finalization; actual history creation and active-ID registration share the force-stop lock. The bounded final adversarial review found no surviving high-confidence defect. DB creation can delay same-engine status/cancel callers; cross-process cancellation is not guaranteed.
- Python/BAT use one reader per pipe, finite process waits/reader joins, and short per-operation sink authorization. Started readers own pipe closure; capture owns logs after setup and defers close for an active log operation. This removes the sink-lock wait but does not bound synchronous physical close or arbitrary filesystem I/O.
- Negative retry/timeout values are rejected at import/update boundaries; supported zero/default behavior remains.
- Board batch-calculation failures display an unknown batch and diagnostic warning rather than fabricated valid-looking batch numbers.

## Architecture assessment

**Facts:** UI dispatch owns opt-in temporary arguments and range selection, not path consent; RunWorker owns
background handoff; engine orchestration owns selection/execution/cancellation;
executor results carry cancellation and background-risk policy; database helpers
own persistence. The complete RunPlan preserves checked execution data. These
boundaries have concrete callers and regression tests.

**Judgment:** keep the existing layer split. The verified defects concern data
scope, missing metadata, premature terminal state, and target identity—not evidence
that thin delegation itself is harmful. Fix each ownership contract instead of
merging MainWindow/RunWorker/engine or adding another service/cache framework.

**Counterargument and limit:** large modules and repeated pure view calculations
still increase maintenance cost; the failed hotspot gate is real evidence of size,
not proof that any arbitrary extraction is safe or faster. Future extractions
should follow an independently testable responsibility (for example run trust or
process output ownership), not a numeric line threshold alone.
