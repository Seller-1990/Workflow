# 全面代码审查与单步运行体验优化

## Goal
恢复上一轮已完成的区间运行和 UI 精修，全面审查当前项目，修复有证据的缺陷和关键路径低效，删除确属冗余的防御与抽象，并降低单步运行的弹窗负担。

## Requirements
1. 审查引擎、执行器、数据库、CLI、UI 及跨层契约；按严重度、复现路径、代码证据和最小修复组织结论。
2. 识别性能问题需说明触发频次、数据规模和实测/复杂度依据；禁止为“简洁”破坏生命周期、取消、风险导入确认等安全不变量。
3. “只运行此步骤”附近新增“本次修改参数”勾选框，默认不勾选。
   - 不勾选：不弹参数页，不修改配置，按步骤既有默认参数直接运行。
   - 勾选：保留现有临时参数对话框和覆盖参数行为。
   - 勾选状态在本次界面会话保留，便于连续调试，不写数据库。
4. 单步运行的风险确认仅针对所选步骤，压缩无关步骤信息；其他模式检查其实际选步范围。保留对未确认外部导入路径的必要安全确认和引擎兜底。
5. 保留工作树已有区间运行和 UI 精修，不回退用户/历史任务改动，不提交、不推送、不打包、不升版本、不引入依赖。

## Acceptance Criteria
- [x] 默认单步运行不调用参数对话框，覆盖参数为空；勾选后才调用。
- [x] 单步运行不显示其他步骤的风险路径；同一步骤存在未确认风险时仍有明确确认。
- [x] 范围化确认后引擎实际能启动，不被第二次全量校验阻断。
- [x] 既有全流程、区间、阶段运行及参数保存/取消语义不回归（最终源码全量 611 passed、1 skipped；含启动停止归属补修）。
- [x] 审查发现逐项区分 confirmed/rejected/needs evidence；修复与暂缓逐项落盘，新增启动回归含外层到达性断言；最终启动 delta 的独立只读复审未发现新的高置信可操作缺陷。
- [x] 全量 pytest 与项目质量门有本轮实际结果；环境限制明确报告（32 个热点基线增长、5 个文件超过 1000 行，strict hygiene 因本地残留失败，不视为全绿；不删除数据、不更新基线）。

## Technical Approach
在步骤编辑器新增轻量 QCheckBox，通过现有 step_run_requested 信号或 MainWindow 状态向分发层传递一次性参数选择，不改 RunWorker 公共执行契约。风险确认复用 build_run_plan/evaluate_run_plan，先按模式选步，再生成范围化 RunPlan；审查并适配确认事务与引擎再校验的全局摘要语义，避免重复弹窗或扩大授权。

### Requirements

- 不在正常父进程退出时盲目终止允许的后台任务；不引入跨进程协调、数据库迁移或新依赖。

### Acceptance
